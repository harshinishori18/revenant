Counterfactual ledger

Three policies, one batch, identical latent state and a shared random stream — a paired comparison, so the gap is the policy, not sampling noise.

Why one retry interval can never be right

Modelled probability of success as a function of how long you wait, by failure reason. A dropped session decays in minutes. An empty account recovers over hours. Any single fixed interval is wrong for one of them at all times — which is the entire opportunity.

Policy sandbox

Change a compliance setting and measure what it does to the money. Every scenario re-runs the counterfactual simulation on the same payments, so the answer is measured rather than estimated. Risk and AML blocks are not tunable — that rule holds in every scenario.

Move a control, then run the scenario.

The compliance guard

These rules are enforced in code, not requested in a prompt. Every proposed action — from the optimiser or from the language model — passes through them, and every verdict is written to the audit log.
